# 技术英文教程：截图拍摄与替换清单

这组图片服务于 [技术英文阅读教程](../../../docs/technical-english-reading.md)，其中 `02-lookup.jpg` 还用作项目 README 的首张预览。每张图只解释一个步骤：自己的原文、原句查词、字母纠错、确认推进、完成练习。

## 统一拍摄准备

1. 选择同一个版本完成五步，记录拍摄日期和站点地址。当前图片于 2026-10-12 取自 [WordTap 官网](https://wordtap.cn/) 在线页面；后续替换时，同步更新本文与两篇文章中的来源说明。
2. 本次使用桌面页面，浏览器视口为 1280 × 720，原始截图为 1265 × 712。等字体、词典与正文加载完成，再截图；静态图统一为 912px 宽，按实际内容保留不同高度。
3. 使用下方同一段示例。关闭“显示音标”和两项自动朗读，让每张图的正文、拼写颜色和提示一致。图 1 不查词，图 2 点击 `cache`，图 3–5 保持这次练习。
4. 截取实际工作区，裁掉浏览器工具栏、操作系统任务栏、课程菜单和页脚。保留正在解释的控件完整边缘，四周留少量空白；避免把无关设置与大块留白一起带进来。
5. 以正文常见的 720–800px 显示宽度检查一遍：读者应能看清原句、输入内容和关键提示。若字太小，缩小截图范围；五张图无需强行裁成相同高度。
6. 静态图分别保存为下面的原文件名。若改用 PNG，同时更新所有引用；不要把 PNG 内容只改名为 `.jpg`。截图保持真实界面，图注放在正文里。

```text
The cache stores recent responses.
Clear it before you retry the request.
```

**文件：`01-read.jpg`。** 粘贴两句英文，点击编辑区外，让可点读正文出现。此时不要查词，也不要进入跟打。

**验收：** 输入区与阅读区都显示相同的两句，正文清晰，跟打入口完整；不要从课程选择器中间开始截。

*图 1｜用自己的材料开始。上方粘贴原文，下方点词阅读；读完后，可从同一工作区进入“文章跟打”。*

**验收：** 这是等待确认的状态，不能拍成已完成 2 / 2 句。正确提示和确认按钮都清晰可见，与图 3 的范围尽量一致。

*图 4｜输对与完成是两个状态。第二句已输入正确，等待你按 Enter 或点击“完成练习”确认；此时进度仍是“已完成 1 / 2 句”。*

**文件：`05-completed.jpg`。** 在图 4 的状态按 Enter 或点击“完成练习”。

*图 5｜一小段练习有明确终点。“已完成 2 / 2 句”记录本次输入进度；可以重新练习，也可以退出跟打回到阅读。*

## Markdown 显示尺寸

教程、博客和项目 README 使用 HTML `img` 标注原始显示宽度：静态图为 `width="912"`，动图为 `width="1000"`；同时设置对应像素宽度、`max-width: 100%` 与 `height: auto`。宽正文不会放大图片，窄正文按比例缩小。只指定宽度，不写固定的高度，避免窄屏时比例变形。

每张步骤图都链接到原图，便于查看完整像素。[GitHub 的渲染说明](https://github.com/github/markup#github-markup)说明它会过滤行内样式，因此同时保留 `width` 属性，配合它已有的图片宽度限制；博客则同时使用行内样式和现有的响应式图片规则。`max-width` 的容器约束见 [MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/max-width)。纯 Markdown 图片语法没有统一的尺寸参数，最终显示仍受渲染器的 HTML 支持和样式规则影响。

尺寸约束能避免额外放大，无法恢复 JPEG 编码或 GIF 调色板已经丢失的细节。
