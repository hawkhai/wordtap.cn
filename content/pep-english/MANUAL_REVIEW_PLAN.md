# PEP English 逐篇人工校对计划

## 原则

- 最终清单中的每一篇文章都必须由人工打开原始 PDF 对应页，逐行对照正文；抽样、正则校验、OCR 置信度和构建通过均不能替代人工校对。
- 一次只处理一篇。当前篇没有形成明确结论和证据前，不进入下一篇。
- 台账初始状态只能是 `pending`，程序不得自动写入 `passed`。
- 当前 438 篇是校对基线，不是假定正确的最终目录。发现练习碎片、漏文、错分、跨页断裂时，必须执行删除、补录、拆分或合并。
- 若校对后最终文章集合发生变化，新文章必须新增台账行；原基线行必须以 `removed`、`merged` 或 `split` 结案，并指向替代文章，不能直接消失。

## 单篇校对流程

每篇必须依次完成以下项目：

1. 在台账把该篇从 `pending` 改为 `in_review`，记录校对人和开始时间。
2. 核对来源 PDF 的 MD5 与课文审计字段一致，打开 `pageStart` 至 `pageEnd` 原页；跨页文章同时检查前后各一页，确认没有漏接或误接。
3. 判断它是否属于收录范围：完整阅读语篇、完整范文或连贯对话。题干、答案选项、词表、语法填空、教学指令和不完整片段一律退回处理。
4. 核对文章边界：标题、开头、结尾、段落顺序、双栏顺序、图片文本框、跨页续接均与原页一致。
5. 逐行核对正文，修正 OCR 错字、断词、行末连字符、标点、引号、专名、数字、大小写和异常空格；不得凭语言习惯改写教材原文。
6. 核对元数据：教材册、Unit、Section、标题、起止页和提取方式。
7. 把每一处修改写入 `reviewed-corrections.json`，至少记录 `groupId`、页码、原文、改文、原因和对应文章 ID；结构性拆分、合并、删除另写明确说明。
8. 重新生成该册数据，确认 `text === blocks.map(...).join("\n")`，并人工复读修改后的整篇正文。
9. 在台账写入证据位置、修改数和结论：`needs_fix`、`recheck` 或 `passed`。只有完整复读无误后才能标记 `passed`。

## 风险与复核

- `risk=high` 的文章优先做两轮人工核对。目前高风险主要来自七下、八下的 OneOCR 页面。
- OCR 文章第一轮逐字核对，第二轮只看修改后文本与原页，不参考第一轮结论。
- 文本层文章也必须逐篇核对；`risk=normal` 只表示没有 OCR 风险，不表示内容正确。
- 每完成一册，运行数据校验、类型检查和生产构建，并抽查该册所有修订是否仍能在原页定位。但册级命令不能替代逐篇状态。

## 完成标准

只有同时满足以下条件才算完成：

- 最终 manifest 中每个课文 ID 都有一条 `passed` 台账记录和原页证据。
- 所有基线行均有最终处置，不存在 `pending`、`in_review`、`needs_fix` 或孤立的删除行。
- 所有拆分、合并和新增文章均能双向追溯。
- OCR 高风险文章已完成第二轮复核。
- 逐册重新生成和普通验证通过；17 册全部获得后，严格完整性验证也通过。
